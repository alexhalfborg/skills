# Ignite Design System

> **This is a worked example, not a live brand.** It shows the shape a `brands/<id>/design.md` takes
> — the token frontmatter that `compose-lockup` and `explore-visual-ideas` read for typeface and colour, and
> the prose that `build-landing-page` reads in full. Copy it to `brands/<id>/design.md` and replace every
> value with the brand's own. Nothing in the engine reads this file.

## Brand & Style

The "Ignite" design system is built around energy, immediacy, and high-impact communication. It evokes a sense of urgency and modern vitality, making it ideal for platforms that require user attention and decisive action.

The aesthetic leans toward a **High-Contrast / Bold** style, but expresses that boldness primarily through restrained surfaces and selective red accents rather than tinted chrome. Neutrals stay neutral so the deep red primary can carry maximum impact wherever it appears.

## Colors

The palette pairs a deep, pure red primary against warm-but-neutral surfaces, augmented by high-voltage secondary and tertiary accents.

- **Primary (#b80000 light / #ffb4b4 dark):** A deep, true red used for core actions, branding, and highlighting critical information. Pure hue with no orange or pink undertone, giving it a more serious, authoritative feel than a vermillion or scarlet. In dark mode it lifts to a soft pink tint for accessible contrast against deep surfaces.
- **Secondary (#2100c6 light / #c2c1ff dark):** A deep electric violet-blue that provides a jarring, high-energy contrast to the primary red, used for secondary interactions and digital-first accents.
- **Tertiary (#6c5e00 light / #e1c700 dark):** A dark olive-yellow in light mode that brightens to a saturated gold in dark mode, used for warnings, highlights, or to draw the eye to specific data points.
- **Neutrals:** Warm grays with a faint cream/stone character — _no_ red tint. Surfaces, containers, borders, and on-surface text all sit in this neutral ramp so the red primary remains a true accent.

The system supports both **Light** and **Dark** modes. Light mode uses near-white warm-gray surfaces (`#fafaf9`, `#f1f0ec`); dark mode uses a deep warm near-black (`#161513`). In both modes the warmth comes from the gray family itself, not from primary bleed.

### Surface philosophy

This is a deliberate departure from default Material 3 behavior. M3 normally tints surfaces with a small amount of primary to make the system feel cohesive — for a red brand, that produces pink-tinted cards, containers, and chrome. Ignite rejects this tradeoff: red appears only where red means something (primary actions, brand marks, the `*-container` emphasis variants), and never bleeds into structural neutrals.

Practical implications:

- Cards, panels, page backgrounds, and side surfaces all render in warm gray.
- The `surface-tint` token is still set to primary (`#b80000`) for compatibility with M3 consumers that apply elevation tint at runtime — but the static `surface-*` tokens in this file have already been computed without that tint.
- If you're using Material You / dynamic color, override the tint-blend step or it will reintroduce the pink.

### Container variants

This system uses a non-standard Material 3 pattern: `primary-container`, `secondary-container`, and `tertiary-container` are visually **louder** than their base counterparts (e.g. `primary-container` is `#e60000`, brighter than `primary` at `#b80000`). This is intentional and supports a "bold container" component style where filled cards and emphasis surfaces lead with maximum saturation. Use these sparingly — they're the place where red is meant to dominate. Standard cards should use `surface-container` (neutral), not `primary-container`.

## Typography

The typography strategy pairs the compact, condensed **Zain** for impact text against the friendly, highly readable **Nunito** for everything else. Both run at restrained weights so the deep brand colors carry the visual force rather than thick letterforms.

- **Zain** is used for the display and headline scales at **Regular (400)**. Its narrow character width means it still reads as confident and prominent at large sizes without needing to go bold. Slight negative letter-spacing keeps the condensed letterforms cohesive.
- **Nunito** is used for titles, body, and labels. Titles and labels sit at **Semibold (600)**, body at **Regular (400)** — a one-step difference that creates clear hierarchy without heavy contrast.

### Font stacks

Two fallback stacks are defined in `typography.fontStacks`:

- `display`: `Zain, "Arial Narrow", "Helvetica Neue", system-ui, sans-serif` — keeps the condensed feel if Zain fails to load
- `body`: `Nunito, system-ui, -apple-system, "Segoe UI", Roboto, sans-serif` — falls back to native system sans-serifs

### Implementation notes

- **Zain weight constraint:** Zain ships in 200, 300, 400, 700, 800, 900. There is no 500 or 600 axis, so the only step up from Regular is Bold. The system stays at 400 throughout the Zain scale to preserve a uniform light feel.
- **Letter-spacing:** Display and headlines use negative letter-spacing (-0.005em to -0.02em) because Zain's condensed letterforms benefit from tighter tracking at large sizes. Body and small labels use slight positive letter-spacing (0.01em to 0.03em) for legibility.
- **Emphasis token:** `emphasis` is intentionally sizeless — it only specifies weight (600), so it inherits font-size and line-height from whatever element it's nested inside. Use it for inline `<strong>` styling within body text. Note that 600 matches the title and label weights, so it won't stand out _against_ those tokens — it only emphasizes against body text at 400.
- **Loading footprint:** With these defaults, you only need to load **Zain at 400** and **Nunito at 400 + 600**. That's three font files, half the original brand spec.

## Layout & Spacing

The system utilizes a 4px-based rhythmic scale. The layout philosophy is a **Fluid Grid** that adapts to various viewport widths while maintaining consistent internal density.

- **Mobile:** 4-column grid with 1rem gutters.
- **Desktop:** 12-column grid with 1.5rem gutters and a maximum container width of 1280px.
- **Density:** Spacing is kept tight to maintain the "energetic" feel of the brand, utilizing stack gaps of 2rem between major content blocks.

## Elevation & Depth

Depth is conveyed through **Tonal Layers** rather than heavy shadows. Neutral surfaces are distinguished by slight luminance shifts across the `surface-container-*` ramp, plus subtle 0.5–1px borders in the neutral outline tones.

Where elevation is required for interactivity (like modals or floating buttons), a "hard" ambient shadow with very low blur and higher opacity is used to maintain the crisp, high-contrast aesthetic. In dark mode, elevation also leans on the `surface-container-*` ramp (which gets progressively lighter from `lowest` to `highest`) rather than shadow alone.

## Shapes

The shape language is **Rounded**, striking a balance between the deep brand colors and the friendly typography.

- **Standard Elements:** Buttons and input fields use a 0.5rem (8px) corner radius.
- **Large Elements:** Cards and containers use a 1rem (16px) radius.
- **Extra Large:** Modals or prominent sections use 1.5rem (24px) to create a distinct, modern container feel.

## Components

- **Buttons:** Primary buttons use the deep `#b80000` (light) / soft pink `#ffb4b4` (dark) background with `label-lg` text. Secondary buttons utilize the electric violet for clear differentiation of alternative actions. Tertiary/ghost buttons sit on neutral surfaces with a neutral outline.
- **Cards:** Use `surface-container` (warm neutral gray) backgrounds with a subtle neutral border and 1rem corner radius. Card headers use `title-md` or `title-lg`. Avoid using `primary-container` for default cards — that's reserved for explicit red-on-red emphasis surfaces.
- **Inputs:** Clean, 2px borders using the neutral outline color, shifting to the primary red when focused to signal active engagement. Labels use `label-md`, helper text uses `body-sm`.
- **Chips:** Small, high-contrast badges using `label-sm` text on the tertiary olive/gold for status alerts or the secondary violet for categorical tags. Default chips use neutral surface tones.
